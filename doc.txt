Gap Analysis: What the Plan is Missing or Too High-Level On
The plan.txt is detailed for Phases 1-5 but gets progressively thinner. Here are the specific gaps when compared to the SOW's AI requirements:

1. No Multilingual Support (English + Hebrew)
The SOW explicitly requires both English and Hebrew. The plan has zero mention of i18n for prompts, LLM responses, or memory storage. This affects every AI component — prompts, nudge text, food recognition labels, symptom triage rules.

2. Glycemic Load Prediction is Underspecified
The SOW lists "Glycemic load prediction" as a distinct AI capability. The plan mentions glycemic_load as an optional field in FoodLog but doesn't describe how it's actually predicted. Is it from the nutrition API? From the LLM? From a custom model?

3. Portion Size Detection is Missing
The SOW lists "Portion size detection" under AI-Powered Food Tracking. The plan's food recognition wrapper doesn't address this at all.

4. Risk Prediction is Vague
The SOW's Contextual Awareness Engine outputs include "Risk prediction." The plan's nudge engine covers alerts and pattern insights but doesn't describe a risk scoring model or how risk levels are calculated.

5. Dataset Preparation Pipelines / Model Improvement Workflows
The SOW's Knowledge Directory includes "Dataset preparation pipelines", "Feedback loop from user interactions", "Model improvement workflows", and "Human-in-the-loop validation system." The plan's Phase 8 only covers content retrieval — none of the ML ops / training pipeline aspects.

6. Location/Time-Based Patterns
The SOW lists "Location/time-based patterns" as an input to the Contextual Awareness Engine. The plan doesn't include any location data ingestion or time-pattern analysis beyond CGM timestamps.

7. No Physician-Shareable Report Generation
The SOW mentions "Physician shareable reports" under CGM Insights. The plan doesn't address report generation or export.

8. Emergency Health Alerts
The SOW lists "Emergency health alerts" under Notification Services. The plan's nudge engine has glucose_alert but doesn't define an emergency escalation path.

9. app/api/ Duplication Issue
There are two API layers: the working endpoints.py (root level) used by main.py, and the empty app/api/ directory structure from the plan. The plan's Phase 1 describes migrating to app/api/ with JWT auth, but this hasn't been done — the old endpoints.py with X-User-ID query params is what's actually running. main.py:14-25 main.py:1

10. LangGraph Pipeline Not Extended
The plan describes adding a health_correlation node between ltm_gate and chat (Phase 4), but the current graph is still the original 5-node linear pipeline with no conditional edges. builder.py:22-34
